# A5: Layout

_Roadmap item A5 of [the toolkit-replacement plan](2026-10-20-toolkit-replacement.md) (tracking: [uiuc-csid/ilw-ui#9](https://github.com/uiuc-csid/ilw-ui/issues/9)). Replaces `ilw-content`, `ilw-columns`, `ilw-grid`, `ilw-spacer`, `.ilw-container` and `.ilw-width-*` with CSS and Svelte, and gives breadcrumbs (B4) and the page title (B5) the toolkit's `width` breakout that [the page-chrome plan](2026-10-20-page-chrome.md) deferred to this item._

What they do today, in short:

- **`width="full|auto|page"`** is reimplemented in each element's shadow CSS: `full` and `auto` break out of the parent with `left: 50%; margin-inline: -50vw; width: 100vw`; `auto` (and `page`) then put the content back at `--ilw-margin--side`, which `toolkit.css` sets on `:root` to `max(1.875rem, calc(50cqw - 35.625rem))`. Breadcrumbs' `auto` is the same as `full` (no inner margin), and the page title maps `page` and `auto` to the same thing. `100vw` includes the scrollbar, which is why `ilw-page.ilw-margin` sets `overflow-y: hidden`.
- **`.ilw-width-full`** in `toolkit.css` is only the full-width button (`.ilw-button.ilw-width-full`, `.ilw-buttons.ilw-width-full`). The `ilw-page` README says a block with that class breaks out of the page margins, but no rule does it.
- **`.ilw-container`** has no layout rule in the toolkit: its only use is a part of `ilw-input`'s toggle slider.
- **`ilw-content`** wraps prose: the `ilw-format` type scale, plus `mode` (`introduction`: centred, max 1000 px + 3.75 rem, larger text; `lede`: the same width, italic, optional left `decoration` bar; `inset`: smaller headings and big padding), `theme`, `align`, `width`, `padding`, `transparent`.
- **`ilw-columns`** is a flexbox row, one shadow `<div>` per child, `mode` sets each child's `flex-grow` (`1x2`, `2x1`, `1x3`, `3x1`, `1x2x1`, `sidebar-left|right` at a fixed 280 px), `reverse`, `gap` (0, 30 px for sidebars), `padding` (`0 0 40px 0`), `theme`, `width`. It stacks at 700 px, by media query and by container query. The CSS-only form is `div.ilw-columns` with `ilw-2x1` etc., a 20 px gap and `ilw-fixed`.
- **`ilw-grid`** is `<ul>` with `repeat(auto-fit, minmax(<innerwidth>, 1fr))`, 10 px gap, `padding: 0 0 40px 0`, equal-height items. CSS-only: `ul.ilw-grid`/`div.ilw-grid`, `--ilw-grid--gap`, `--ilw-grid--template-columns`, `ilw-fixed`.
- **`ilw-spacer`** is a `<div role="presentation">` with `padding-bottom: <height>` (default 20 px).

## Decisions

- **Widths are one set of classes, written once** (`width.css`): `.ilw-width-full`, `.ilw-width-auto`, `.ilw-width-page`, with the toolkit attribute's meaning: `full` breaks out to the edges of the page, `auto` breaks out but keeps the content at the side margin, `page` keeps the box at the side margin. Every component's `width` prop renders one of these classes; breadcrumbs, page title, content, columns and grid have no breakout rules of their own.
- **Container units, not `100vw`.** The breakout is `margin-inline: calc(50% - 50cqw)`: the parent's half-width minus the container's. `.ilw-page` becomes an inline-size container, so `cqw` is the page's content box, without the scrollbar, and nothing scrolls sideways. Like the toolkit's `left: 50%`, it assumes the parent is centred in the page (true for `main` with `.ilw-margin`). Without any container, `cqw` falls back to the viewport, as the toolkit does. No overflow clipping on `.ilw-page`: it would cut off focus rings at the page's edge, and the breakouts don't overflow at any width the tests check.
- **The side margin** is `--ilw-margin--side`, set on `:root` in `width.css` to the toolkit's value, `max(1.875rem, calc(50cqw - 35.625rem))` (1140 px of content, at least 30 px each side). An unregistered custom property keeps `cqw` unresolved, so it measures the container where it's used. `page.css` (`.ilw-margin`) and `footer.css` read it too, with the same fallback, so a site changes every margin in one place. Our breadcrumbs' `auto` keeps the trail at the margin, as the toolkit's docs describe (its code makes `auto` the same as `full`).
- **`.ilw-container`** is ours: an inline-size query container (`container-type: inline-size`). It is the boundary for both the breakouts (a `.ilw-width-full` inside it spans the container, not the page) and the columns' 700 px stacking query. The toolkit has no layout rule of that name, so nothing to match.
- **`.ilw-width-full` keeps the button meaning.** The breakout skips `.ilw-button`, `.ilw-buttons` and `button` (selector `:where(:not(…))`, so it still weighs one class), where the class keeps meaning "full-width button".
- **Toolkit class names are kept** (`ilw-columns`, `ilw-grid`, `ilw-1x2`, `ilw-2x1`, `ilw-1x3`, `ilw-3x1`, `ilw-1x2x1`, `ilw-fixed`). The rest, and the element attributes, become modifier classes named after the element (`ilw-columns--sidebar-left`, `ilw-content--lede`), as in page chrome. Themes are the A1 `theme` attribute (`theme="blue"`), as on `<section class="ilw-format" theme="blue">`; A1 already maps every toolkit theme name, including `gray` and the gradients.
- **Columns stay flexbox.** A mode weights children (`2x1`: the first child is twice the others, however many there are), which flex can say and a grid template can't without knowing the count. The grid is CSS grid. Columns stack below 700 px by container query (the nearest `.ilw-container` or `.ilw-page`) and, as upstream, by media query, so a page with no container still stacks.
- **No `padding` props.** The toolkit's `padding` attribute is an inline style on a shadow wrapper; ours would clash with the `auto` width's side padding, and consumers run `style-src-attr 'none'`. Spacing is the page's: margins, `Spacer`, or a class in the site's stylesheet. So the element's default `padding: 0 0 40px 0` on columns and grid isn't copied (the CSS-only classes have none either).
- **Svelte sets only custom properties**, with `style:--name={value}` (CSSOM, allowed under the consumers' CSP): `gap` on columns and grid, the grid's item width, the spacer's height.
- **Spacer:** `<div class="ilw-spacer" aria-hidden="true">` with `block-size: var(--ilw-spacer--height, 20px)`. `aria-hidden` instead of `role="presentation"`, which means nothing on an empty `div`.
- **`.ilw-content` carries `.ilw-format`.** The type rules of `ilw-content` are the A2 prose rules; the contract puts both classes on the box, and `content.css` adds only the box, the modes and `ilw-content`'s smaller `h1` bottom margin.

## Markup contract

### Widths and container

```html
<main class="…">                                   <!-- inside .ilw-page.ilw-margin -->
  <div class="ilw-width-full">…</div>             <!-- edge to edge -->
  <div class="ilw-width-auto" theme="blue">…</div> <!-- background edge to edge, content at the side margin -->
  <div class="ilw-width-page">…</div>             <!-- at the side margin (for a page without .ilw-margin) -->
  <div class="ilw-container">…</div>              <!-- query container and breakout boundary -->
</main>
```

### Content

```html
<div class="ilw-content ilw-format" theme="gray">  <!-- + ilw-content--introduction | --lede | --inset,
                                                      ilw-content--center | --right, ilw-content--decoration,
                                                      ilw-content--transparent, ilw-width-* -->
  <div class="ilw-content-inner">
    <h2>Programs</h2>
    <p>…</p>
  </div>
</div>
```

- `.ilw-content` paints `--ilw-color--background`/`--ilw-color--text` (a theme attribute on it restyles it), and breaks out with a width class. `.ilw-content-inner` holds the mode's width and padding, the alignment and the decoration (the toolkit's `content-inner` and `content-padding`, merged; the centred lede's bottom rule is `::after`, not a `<div role="presentation">`).
- Modes, from `toolkit.css`: introduction text 1.375/2.2 rem and `em` 2.25 rem; lede italic 1.375/2.2 rem; inset headings 1.813 rem and padding `3rem 6rem`, then `3rem 2.2vw` ≤ 1450 px, `1.875rem` ≤ 1000 px, `1.875rem 1.25rem` ≤ 800 px. Introduction and lede: max width `calc(1000px + 3.75rem)`, centred, padding `0 1.875rem`. Decoration: a 6 px `--ilw-color--control-accent` bar on the left (right when right-aligned; a 150 px bottom rule when centred).
- `--transparent` sets `--ilw-color--background: transparent`, as upstream.

### Columns

```html
<div class="ilw-columns ilw-2x1">                  <!-- | ilw-1x2 | ilw-3x1 | ilw-1x3 | ilw-1x2x1 |
                                                      ilw-columns--sidebar-left | --sidebar-right;
                                                      + ilw-columns--reverse, ilw-fixed, ilw-width-*, theme -->
  <div>…</div>
  <div>…</div>
</div>
```

- Gap `--ilw-columns--gap` (20 px; 30 px for the sidebar modes, as upstream), sidebar width `--ilw-columns--width--sidebar` (280 px). Children are `flex: 1 0 0` with `min-width: 0`, so long words don't push the row wider than its box.
- `--reverse` is `row-reverse` on wide screens only. Use it only when one side is decorative: the reading order stays the DOM order (the toolkit README's advice).

### Grid

```html
<ul class="ilw-grid">                              <!-- or <div>; + ilw-fixed, ilw-width-*, theme -->
  <li>…</li>
  <li>…</li>
</ul>
```

- `grid-template-columns: var(--ilw-grid--template-columns, repeat(auto-fit, minmax(min(var(--ilw-grid--item-width, 250px), 100%), 1fr)))`, gap `--ilw-grid--gap` (10 px). The `min(…, 100%)` makes an item wider than the grid shrink to it, which the toolkit README promises and its code doesn't do. Items stretch to the row's height and their only child fills them.
- A list, as upstream, so screen readers announce the count.

### Spacer

```html
<div class="ilw-spacer" aria-hidden="true"></div>  <!-- height: --ilw-spacer--height, default 20px -->
```

### Breadcrumbs and page title

The B4/B5 markup gains a width class on the outer element: `<nav class="ilw-breadcrumbs ilw-width-auto">`, `<div class="ilw-page-title ilw-width-full">`. `breadcrumbs.css` and `page-title.css` drop the declarations that would fight it (the breadcrumbs' `padding` shorthand becomes `padding-block`; the page title loses `width: 100%`). The page title's `auto` keeps its text, not its box, at the margin, with its own `--ilw-page-title--main-margin` (as upstream, which allows for the plate's padding).

## Svelte

Each renders exactly the markup above; `children` is the content.

- `Content`: `mode` (`'introduction' | 'lede' | 'inset'`), `align` (`'left' | 'center' | 'right'`), `decoration`, `transparent`, `theme`, `width`, `class`.
- `Columns`: `mode` (`'1x1' | '1x2' | '2x1' | '1x3' | '3x1' | '1x2x1' | 'sidebar-left' | 'sidebar-right'`), `reverse`, `gap`, `theme`, `width`, `class`. Children are the column `<div>`s.
- `Grid`: `as` (`'ul' | 'div'`), `itemWidth` (the toolkit's `innerwidth`), `gap`, `theme`, `width`, `class`. Children are the `<li>`s.
- `Spacer`: `height`.
- `Breadcrumbs`, `PageTitle`: a new `width` prop (`'full' | 'auto' | 'page'`). `PageTitle`'s `page` renders `ilw-width-auto`, because the toolkit page title treats `page` as `auto`.

`width` is `'full' | 'auto' | 'page'` everywhere (type `LayoutWidth`, exported).

## Tests

- **DOM contract and geometry** (play functions): each component's classes and attributes; the breakouts measured inside `Page margin` (a `full` box is as wide as the page, `auto`'s content starts at the side margin, `page` sits inside it, and the document never scrolls sideways); columns' flex weights and stacking inside a 600 px `.ilw-container`; the grid's column count for a given width; the spacer's height and `aria-hidden`.
- **Keyboard:** none of these has keyboard behaviour, so no e2e spec.
- **axe:** every story. Themed content and columns cover each theme's contrast.
- **Story descriptions and page context:** every story has the AGENTS.md "Stories" comment (summary, **Why:**, **Review:**) and renders with `styles.css` only, inside the page shell, with headings, prose and images in each region so the spacing and breakouts read as on a page.
- **Parity:** `stories/parity/Layout.parity.stories.svelte` (content modes, columns modes, grid, spacer) and `stories/parity/Width.parity.stories.svelte` (the three widths on content, columns, breadcrumbs and page title inside a page with side margins).
