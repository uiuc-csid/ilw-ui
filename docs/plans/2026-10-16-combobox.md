# `Combobox`: single-select filtering combobox on Zag

_The first Zag-based component. Builds on the harness from [the scaffold plan](../old-plans/2026-10-16-ilw-ui-scaffold.md) (steps 4–7 there define the test layers, guard, styles and docs every component follows)._

## Context

ta-manager's `enhanceSelect` (`src/static/forms/app.js:140-346`) turns every `select[data-combobox]` into a hand-rolled, `innerHTML`-built combobox. It has three ARIA defects: `aria-expanded` is wrong while the list is open, group headers have no role, and Escape drops focus to `<body>`. ta-manager plans to replace it with an app adapter, `lib/ui/ComboboxSelect.svelte`, built over **`ilw-ui` `Combobox`** (Zag's combobox machine). The adapter keeps ta-manager's DOM contract (E2E-DEV_TIPS §4, `docs/plans/2026-10-16-frontend-svelte-islands-contracts.md`, "Combobox"):

- The hidden `<select data-combobox id>` stays the value source. A commit sets `select.value` and dispatches a bubbling `change`. `data-comboboxed="1"` is set on the select. **These live in the adapter, not here.**
- `span.combobox` (with `cb-block` for block layout) > `input.combobox-input#<id>-cb[role=combobox]` sits right after the select. `label[for]` is re-pointed to `<id>-cb`.
- The popup is `div.combobox-popup#<id>-popup[role=listbox]`.
- The list opens at 2 characters. It shows at most 200 options, then a "…N more" row. `<optgroup>`s become groups.
- Matching is a case-insensitive substring search of the trimmed text over each option's `data-search`, or its label when there is none. `data-search` usually holds the label plus the netid. With no match, the list shows a disabled "No matches" row.
- Unmatched free text stays in the input. On blur, the combobox commits only an exact or unique match.

There are four uses, all single-select over a static list rendered client-side, with no server search: `#avoidFacSel`, `#avoidStuSel`, `#prefStuSel` and `/course` `.ci-add`. Playwright tests in ta-manager write into `.combobox-input` without matching an option, and select `#avoidFacSel-cb`. Those tests must pass unedited.

Free-text pickers (professor, course, thesis search) are the separate **`Autocomplete`**, which is not part of this plan.

## Decisions

- **Zag 1.44.0**, the newest release at least two weeks old (1.46.0 came out on 2026-10-11). Pin exactly, in lockstep: `@zag-js/combobox`, `@zag-js/svelte`, as `dependencies`. Pinning those two pins every transitive `@zag-js/*` package at 1.44.0. `@floating-ui/dom` comes in with a caret range; the lockfile pins it. Read the 1.44.0 source, not the website docs.
- **Single select only.** No `multiple` until a consumer needs it.
- **We render the markup and spread Zag's props on it,** with ids set through Zag's `ids` option. That way the DOM contract above is ilw-ui's own contract, and the adapter stays thin.
- **No hidden form input.** Zag puts `name` on the visible input, so `FormData` would get the label text. ta-manager's select is the value source, so `Combobox` takes no `name`. The README says so.
- **No Zag positioner.** The popup is placed with CSS (`span.combobox { position: relative }`, popup `position: absolute; top: 100%; inset-inline: 0`). This drops Floating UI's inline `style` attribute, which a strict `style-src` without `'unsafe-inline'` may block. Verify in step 1 that the machine works with no positioner element. If it doesn't, render the positioner but don't spread its `style`.
- **The "…N more" row** is a disabled option, `role=option aria-disabled=true`, that `isItemDisabled` skips. Its text is the legacy "…N more — keep typing to narrow". The "No matches" row is built the same way. A non-option child of a listbox fails axe `aria-required-children`.
- **Matching lives in `core`** (framework-agnostic and unit-tested). `Combobox` filters through it from `onInputValueChange`, following the reassign-items pattern in Zag's Svelte example.

## API

```ts
// core
export interface ComboboxItem { value: string; label: string; search?: string /* defaults to label */; group?: string }
export function filterItems(items: ComboboxItem[], query: string, max: number): { shown: ComboboxItem[]; more: number };
export function blurMatch(items: ComboboxItem[], text: string): ComboboxItem | null; // exact label/value match (case-insensitive, trimmed), else the single search match, else null
```

`Combobox.svelte` props:

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `id` | `string` | required | input id. The adapter passes `<select id>-cb`. |
| `popupId` | `string` | `${id}-popup` | listbox id. The adapter passes `<select id>-popup`, per ta-manager's contract. |
| `items` | `ComboboxItem[]` | required | groups in first-seen order |
| `value` | `string \| null` | `null` | selected value (controlled) |
| `onchange` | `(value: string \| null, item: ComboboxItem \| null) => void` | required | on commit: an option chosen, or blur (match → that item; unmatched or empty text → `null`, as the legacy code clears the select) |
| `placeholder` | `string` | `''` | |
| `minChars` | `number` | `2` | typing opens the list at this length; ArrowDown and Alt+ArrowDown always open it |
| `max` | `number` | `200` | |
| `block` | `boolean` | `false` | adds `cb-block` |
| `disabled`, `invalid`, `required` | `boolean` | `false` | |
| `labelId` | `string` | — | id of the consumer's `<label>`. It becomes the listbox's `aria-labelledby`. Without one, the listbox falls back to `aria-label` = `placeholder`. |

Free text: `allowCustomValue: true`. Text that doesn't match stays in the input and never calls `onchange`.

## DOM contract

```html
<span class="combobox [cb-block]" data-scope="combobox" data-part="root">
  <input id="{id}" class="combobox-input" role="combobox" type="text"
         aria-autocomplete="list" aria-expanded="true|false" aria-controls="{popupId}"
         aria-activedescendant="{option id while one is highlighted}" autocomplete="off" />
  <div id="{popupId}" class="combobox-popup" role="listbox" aria-labelledby="{labelId}" hidden?>
    <!-- with groups -->
    <div role="group" aria-labelledby="{group label id}">
      <div role="presentation" class="combobox-group-label">{group}</div>
      <div role="option" aria-selected="false" data-value="{value}" data-highlighted?>{label}</div>
    </div>
    <!-- past max -->
    <div role="option" aria-disabled="true" class="combobox-more">…{N} more — keep typing to narrow</div>
    <!-- no matches -->
    <div role="option" aria-disabled="true" class="combobox-empty">No matches</div>
  </div>
</span>
```

The README documents exactly this, including which attributes come from Zag.

**Spike findings (2026-10-16).** `stories/ComboboxSpike.svelte` passed on Chromium and WebKit, five runs in a row.

- **The combobox works with no positioner.** `trackPlacement` and `reposition` look the positioner up by id and do nothing when it's missing. No errors were thrown. Decision kept: CSS positioning, no Floating UI `style` attribute.
- **`ids` work as planned.** `ids.input` / `ids.content` / `ids.item(value)` give `<id>`, `<popupId>` and the option ids. Values with spaces or colons (`has space`, `x:y`) highlight and commit correctly: the machine finds options with `CSS.escape`.
- **The listbox's `aria-labelledby` defaults to `combobox:<id>:label`**, an element that doesn't exist. Set `ids.label = labelId`. With no `labelId`, override the attribute with `aria-label` after spreading the content props.
- **Zag 1.44.0 bug: `openOnChange` as a function sees the text from before the keystroke.** The guard runs before `setInputValue`, so `length >= 2` opens on the third character. Workaround: set `openOnChange: false` and call `api.setOpen(inputValue.length >= minChars)` from `onInputValueChange` when `reason === 'input-change'`. Add this to **Known issues** in the README and in a draft upstream issue under `docs/upstream-issues/zag.md`.
- **Already confirmed:**
  - Enter commits and closes, and the input shows the label.
  - Escape closes and keeps focus on the input (fixes ta-manager's bug C).
  - Unmatched free text stays after Tab when `allowCustomValue` is set.
- **The live region is Apple-only** (`isMac() || isIos()`, so it runs on macOS dev machines but not on Linux CI). It exists only while the list is open (an `open`-state effect) and is removed on close. It is a visually hidden `span[role=alert]` on `body`, with styles set through CSSOM. axe passed with it present.
- **`mergeProps` hasn't been needed yet.** Step 3 needs it for the blur commit.
- **The first highlight is applied asynchronously after the list opens.** The example's `onOpenChange` resets the items, so the collection is rebuilt and `CHILDREN_CHANGE` re-applies the highlight. An ArrowDown sent right after `aria-expanded` turns true was sometimes lost: about 1 in 3 full runs failed until the test waited for `aria-activedescendant` first. In step 3, derive the shown items from the input text instead of resetting them on open, so opening doesn't rebuild the collection. Tests should wait for `aria-activedescendant`, not only `aria-expanded`, before the next key.

### 2. `core`: matching

### 3. `Combobox.svelte`

- Write the component to the contract above. Use `useMachine` with getter props. Open from `onInputValueChange`, as described in the step 1 findings (not through `openOnChange`). Highlight the first option only when there is exactly one match, as the legacy code does. `selectionBehavior: 'replace'`. Commit on blur through `blurMatch`, in Zag's `onFocusOutside` / `onInteractOutside` or an input `focusout` combined with `mergeProps`. Choose whichever leaves Zag's state consistent.
- Export it from `src/svelte/index.ts`. Export the types and helpers from `core`.
- **Check:** `pnpm check`. The svelte MCP autofixer reports no issues.

**Done (2026-10-16).** `src/svelte/Combobox.svelte`, with a smoke story (`stories/Combobox.stories.svelte`, `stories/ComboboxDemo.svelte`; the spike is deleted). Findings:

- **The component owns the input text.** Zag derives the text from its collection, which is filtered, so it can't label a value set from outside. `inputValue` is controlled. The component takes text only from `onInputValueChange` reasons `input-change` and `item-select`. It ignores `script` (Zag rewriting the text when the value changes, which wiped free text) and `interact-outside`. An external `value` change sets the text to that item's label, unless it is just this component's own `onchange` echoing back.
- **`mergeProps` runs handlers in reverse order.** `@zag-js/core` uses `callAll(later, earlier)`, so to run before Zag's handler, our props go _last_.
- **ArrowDown/Up on a closed list** sets the query before Zag opens it. The query is the current text, or empty (all items, capped) when the text is the selected label. Setting it before opening means the collection isn't rebuilt after the list opens, so the step 1 highlight race doesn't happen.
- **The "more" and "No matches" rows sit outside Zag's collection.** They are plain `role=option aria-disabled=true aria-selected=false` elements, so arrow keys skip them without `isItemDisabled`.
- **Option ids are `${popupId}-opt-${encodeURIComponent(value)}`.** Raw values with whitespace would make `aria-activedescendant` an invalid IDREF. Group ids are built the same way.
- **The listbox's `aria-labelledby`/`aria-label` are set after Zag's content props are spread,** which overrides Zag's default label id.

### 6. Tests

- **Play (Chromium and WebKit)** tests assert:
  - the exact DOM contract (classes, ids, roles);
  - `aria-expanded` follows open/closed;
  - `aria-activedescendant` matches the highlighted option's id;
  - groups have `role=group` labelled by their header;
  - the list doesn't open below `minChars`;
  - the cap and the "more" row, which isn't selectable;
  - `onchange` fires once per commit, with the value and the item;
  - free text stays and doesn't call `onchange`;
  - blur commits an exact or unique match, and only that;
  - the `disabled` and `invalid` attributes.
- **Playwright (`tests/e2e/combobox.spec.ts`)** checks these APG keys:
  - typing opens the list at 2 characters;
  - ArrowDown and ArrowUp move the highlight and wrap;
  - Alt+ArrowDown opens without highlighting;
  - Enter commits and closes;
  - **Escape closes and focus stays on the input**, which is ta-manager's bug C;
  - Tab moves on, and blur commits a unique match;
  - Shift+Tab goes back.

  Every step asserts focus is never on `<body>`.
- **axe:** every story, including open.
- **CSP:** one Playwright spec loads the open fixture with `<meta http-equiv="Content-Security-Policy" content="style-src 'self'; script-src 'self'">`, injected through `page.route` on the iframe HTML. It asserts there are no CSP violations (`securitypolicyviolation` events) and that the popup is visible and laid out under the input.
- **Check:** `mise run test` and `pnpm check`.
