# C4: Tooltip

Roadmap item C4 ([toolkit replacement](2026-10-20-toolkit-replacement.md), uiuc-csid/ilw-ui#9): a `Tooltip` island replacing `<ilw-tooltip>`.

## Upstream

`web-illinois/ilw-tooltip` (the vendored `toolkit.js` has the same code): a Lit element with a `trigger` and a `content` slot.

- Look: a 200px-max bubble, `--ilw-color--background` / `--ilw-color--text` of its theme (`theme="blue"` sets the `[theme=blue]` palette), 8px radius, `2px 0 4px 4px` 10% black shadow, `8px 12px` padding, `400 1rem/1.375rem` sans, a 6px CSS-triangle arrow, 12px from the trigger. `arrow` picks one of eight placements (`top-center` default: the bubble above the trigger, the arrow on its bottom edge).
- Behaviour: shows on `mouseenter`/`focus` of the trigger, hides on `mouseleave`/`blur` (next frame, unless the trigger is still hovered or focused), on any Escape keydown in the document, and on a pointerdown outside. A 500ms long press shows it on touch. Sets `aria-describedby` on the trigger, forces `tabindex="0"` on it, hides the bubble with `opacity: 0` and `aria-hidden`.
- Gaps: moving the pointer from the trigger onto the bubble closes it (only the trigger's `:hover` is checked), which fails WCAG 1.4.13 "hoverable"; the bubble is `position: absolute` inside the host, so an `overflow: hidden` ancestor clips it; `disconnectedCallback` removes freshly bound listeners, so its document listeners leak.

## Design

- `Tooltip` renders `<span class="ilw-tooltip">` around the trigger (the `children` snippet, which spreads `attrs` = `{ 'aria-describedby' }` on its focusable element, as `Field` does) and the bubble `<span class="ilw-tooltip-bubble" role="tooltip" popover="manual">`.
- The bubble is a manual popover (top layer: never clipped), placed by CSS anchor positioning (`anchor-scope` on the wrapper, `anchor-name` on the trigger, its first child, `position-anchor` + `position-area` on the bubble). Where `position-area` or `anchor-scope` isn't supported, a script places it (`position: fixed`, from `getBoundingClientRect`, clamped 8px inside the viewport like upstream, measured from the viewport's corner) and follows scroll, resize and either box's size while open. Where `popover` isn't supported, the bubble is toggled with `hidden` instead.
- Open while the wrapper is hovered (pointer events on the wrapper, so the bubble, a DOM descendant, counts) or has focus within. A transparent bridge (`::before`) covers the 12px gap, so the pointer can move onto the bubble (1.4.13 hoverable). Escape closes it while open (1.4.13 dismissible) and is consumed, so a surrounding modal stays open; the next hover or focus reopens it. `open` is bindable (the Open story and controlled use).
- Props: `text` or `content` snippet, `arrow` (the eight upstream values), `theme` (`LayoutTheme`), `id`, `class`, `open`.
- CSS in `src/styles/tooltip.css`, imported by `styles.css` (the per-component partial pattern of modal.css, back-to-top.css).

## Tests

- Stories (`stories/Tooltip.stories.svelte`, page context: a toolbar of icon buttons and a form field's help link): a Fixture (no play), an Open story (axe on the open bubble), play functions for the DOM contract, ARIA wiring, hover, focus, Escape and placement per `arrow`.
- `tests/e2e/tooltip.spec.ts`: focus by Tab shows / blur hides; hover shows; moving onto the bubble keeps it (1.4.13); Escape closes while focus stays; script fallback (CSS.supports stubbed) places it the same.
- Parity: `stories/parity/Tooltip.parity.stories.svelte`, both opened by focus.

## Outcome

Done as designed. The fallback flaked once in 200 runs before it measured the bubble at a fixed spot (its last position left less room, so it wrapped differently); fixed in the component, not the test.
