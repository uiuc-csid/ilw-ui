# E1: `Alert`

Roadmap item E1 ([2026-10-20-toolkit-replacement.md](../plans/2026-10-20-toolkit-replacement.md), uiuc-csid/ilw-ui#9):
dismissible notices for Django `messages` partials and ta-manager's save-error
banner. The toolkit has no equivalent, so there is no parity story; the look
follows the toolkit's surfaces (white palette, brand accents, `ilw-button`
actions, the Modal's round close button).

## Markup (the DOM contract)

```html
<div class="ilw-alert ilw-alert--error" role="alert">
  <svg class="ilw-icon ilw-alert-icon" aria-hidden="true" …>…</svg>
  <div class="ilw-alert-body">
    <span class="ilw-visually-hidden">Error:</span>
    <p class="ilw-alert-title">Your changes weren't saved</p>
    <p>The server didn't answer. Your edits are still in the form.</p>
    <div class="ilw-alert-actions"><button type="button" class="ilw-button">Try again</button></div>
  </div>
  <button type="button" class="ilw-alert-dismiss" aria-label="Dismiss">…</button>
</div>
```

- Variants `--info`, `--success`, `--warning`, `--error`. Role: `status` for
  info, success and warning; `alert` only for errors (roadmap).
- The variant is spoken by a visually hidden label ("Information:",
  "Success:", "Warning:", "Error:"), so it isn't carried by colour and icon
  alone.
- Server templates write the dismiss button with `hidden`;
  `enhanceAlerts(root)` reveals and wires it. Without JavaScript there is no
  button that does nothing.

## Behaviour

- **Dismiss** removes the alert. If focus was inside it (or had fallen to
  `<body>`), focus moves to the next tabbable element after the alert, else the
  previous one, else `<main>` (given `tabindex="-1"` if it has none). Never
  `<body>`. Shared by the component and `enhanceAlerts` (`src/svelte/alert.ts`,
  using `tabbables()`).
- `Alert` (Svelte): `variant`, `title`, `children` (message), `actions`
  (snippet), `dismissible`, `dismissLabel`, `label` (the hidden variant
  label), `open` (bindable), `ondismiss`, `class`. `ondismiss` runs before
  the focus move; if it moved focus itself, that stands.
- **Actions** are the consumer's buttons. An action that removes the alert
  moves focus itself (the demo's "Try again" focuses the form's Save button);
  the README says so.
- **`announce()` is not used.** The role on the alert is the announcement:
  `role="alert"` is spoken when inserted; a status alert rendered with the
  page is read in place. Calling `announce()` as well would read the message
  twice where the screen reader also announces the inserted status region.
  The README points to `announce()` for a status that must be heard when it
  appears after load and the page has no live container for it.

## Colours

The alert always uses the white palette (it redeclares the neutral
`--ilw-color--*` properties), so it is a light card on the blue and orange
themes and a dark one in dark mode, and its buttons and links follow. The
accent (a 6px left stripe and the icon) is per variant, from brand tokens:

| Variant | Light | Dark |
|---|---|---|
| info | Industrial | Industrial lighter 2 |
| success | Prairie | Prairie mixed with white |
| warning | Harvest stripe, Earth icon | Harvest |
| error | Altgeld | Orange |

Icons reach 3:1 against the surface in both modes (WCAG 1.4.11).
