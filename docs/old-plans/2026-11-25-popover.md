# E18: Popover

A new gap item for the [toolkit replacement](../plans/2026-10-20-toolkit-replacement.md) (uiuc-csid/ilw-ui#9): a `Popover`, a button that opens a non-modal panel anchored to it. The toolkit has no popover; the closest pieces are `ilw-tooltip` (hover text only) and the header's megamenu panels (B2), which this generalises. Svelte and React ship together.

Uses: a "Filters" panel of checkboxes over a table, a "?" help button whose panel holds a paragraph and a link, a "More" panel of secondary actions. Not a menu (`role="menu"` is E14 `MenuButton`), not a modal (`Modal`), not a tooltip (`Tooltip`: hover and focus, text only, never focused).

## Design

Native first: the HTML popover API does nearly all of it.

```html
<span class="ilw-popover ilw-popover--bottom-left">
  <button type="button" class="ilw-button" popovertarget="ilw-popover-1">Filters</button>
  <div class="ilw-popover-panel" id="ilw-popover-1" popover>…</div>
</span>
```

- **`popover` (auto) with `popovertarget`.** The browser gives the button an implicit `aria-expanded` and a details relation to the panel, puts the panel next in the Tab order after its button wherever it renders, closes it on Escape and on a click outside (light dismiss), keeps one auto popover open at a time, and returns focus to the button when it closes with focus inside. A close button inside is `<button popovertarget="…" popovertargetaction="hide">`. All of this works with no script, so the markup is a server-template contract like the header's.
- **APG:** the disclosure pattern (a button that shows and hides content), not a dialog: focus stays on the button when the panel opens, and Tab moves into it. No `role` on the panel. The README records the choice.
- **Placement:** the panel is in the top layer, so no `overflow` clips it. Where CSS anchor positioning is supported (`@supports (position-area: top) and (anchor-scope: all)`, as `Tooltip`'s check), `position-area` places it against the button (`anchor-scope` on the wrapper, `anchor-name` on its first child), 4px off, with `position-try-fallbacks: flip-block` so it flips above or below when there's no room. In CSS, not a script-added class, so server markup is placed too. Elsewhere the component places it by script (`position: fixed`, `top`/`left` from `getBoundingClientRect`, clamped 8px inside the viewport, following scroll, resize and size changes while open), as `Tooltip` does; server markup without the component gets the browser's centred popover there.
- **Placements:** `bottom-left` (default: under the button, left edges aligned), `bottom-center`, `bottom-right`, `top-left`, `top-center`, `top-right`, named like `Tooltip`'s `arrow`.
- **Script additions** (the component only): `open` state kept in step with the panel's `toggle` event; focus leaving the wrapper (to another element: Tab past the panel's end, or Shift+Tab from the button) closes it, so an open panel never covers what focus moved to. Light dismiss already covers clicks.
- **Look:** a panel in the page's colours (`--ilw-color--background`/`--ilw-color--text`, so a `theme` attribute and dark mode follow, as on `Tooltip`), a 1px `--ilw-color--border-light` border, 0.5rem radius, the tooltip's shadow, 1rem padding, `max-inline-size: min(var(--ilw-popover--width, 20rem), 100vw - 16px)`. No arrow.
- **Props (Svelte):** `label` (the default button's text) or `trigger` (a snippet taking `attrs` = `{ popovertarget }`, for any other button), `children` (the panel), `placement`, `open` (bindable), `id` (default `ilw-popover-N`), `class`. React: the same, with `trigger: (attrs: { popoverTarget }) => ReactNode`, `className`, `open` + `onOpenChange`. `open` is optional in React: the panel's state lives in the browser (light dismiss, Escape, `popovertarget`), so an uncontrolled popover is the native one and `open` only drives it.
- **No `popover` support** (Safari < 17, Firefox < 125): out of scope; the README says the panel then shows in flow, always open.

## Tests

- Stories (`stories/Popover.stories.svelte` and the React twin, page context: a course roster with a "Filters" popover of checkboxes and a Done button, and a "?" help popover beside a field):
  - **Fixture**: no play; the keyboard spec's page.
  - **Open**: the filters panel open from the start (axe on the open state). Play: the contract (wrapper and placement class, `popovertarget` names the panel, the panel is `[popover=auto]`, the button is the wrapper's first child), the panel under the button with left edges aligned 4px off, its colours, padding and radius.
  - **Toggle**: play: Enter opens and the bound `<output>` says so, focus staying on the button; Enter closes; Done closes and focus returns to the button; opening the help popover closes the filters one.
  - **Phone**: the Open page at a 375 × 667 viewport; the play checks the panel's placement and that it fits.
  - **Placements**: one button per placement; the play opens each and checks where its panel sits.
  - Controls: `label` and `placement` drive the demo's filters popover (not on Placements). The viewport toolbar offers Phone, Tablet and Laptop sizes.
- `tests/e2e/popover.spec.ts`: Enter opens with focus staying on the button, Tab enters the panel, Escape closes with focus back on the button, Tab past the panel's end closes it and focus moves on, Done closes with focus back, Shift+Tab from the button closes it; the script fallback (`CSS.supports` stubbed) places it the same.
- axe on every story; contracts in `stories/contracts/`; `react-ssr` renders the closed React popover like the Svelte one.
- `docs/at-smoke.md`: VoiceOver and NVDA read "Filters, button, collapsed", then "expanded".

## Outcome

Done as designed, in both frameworks, with these findings:

- user-event's synthetic keys and clicks don't reach the browser's light dismiss, so Escape and click-outside are checked only by the keyboard spec (real input); the plays use the buttons.
- The script fallback must switch off `position-area` inline: where anchor positioning exists but the script places the panel (the spec stubs `CSS.supports`), `top`/`left` were offsets inside the position area.
- React's server render spells `popoverTarget="…"` in camelCase; browsers parse it as `popovertarget`, so `react-ssr.test.ts` compares attribute names case-insensitively.
- At the spec's 1280 × 720 viewport the open filters panel covers the "?" button, as it would for a user: the one-at-a-time check lives in the Toggle play.
