# C3: Tabs

_Phase 3 of [the toolkit-replacement plan](../plans/2026-10-20-toolkit-replacement.md) (tracking: [uiuc-csid/ilw-ui#9](https://github.com/uiuc-csid/ilw-ui/issues/9)). Replaces `<ilw-tabs>`: APG tabs, with optional automatic activation and a hash link to each tab. Without JavaScript, the panels show as headed sections._

## Sources read

`web-illinois/ilw-tabs` (builder versions 1.0, 1.1): `src/ilw-tabs.ts`, `src/ilw-tabs.styles.ts`, `src/ilw-tabs.css`, `samples/index.html`, README. What the code does (the README's prose differs in places):

- Light DOM: a `slot="tabs"` `role="tablist"` of `button[role=tab][aria-controls]`, then panels found by `aria-controls` id. Hidden panels get `data-ilw-tab-visible="0"` (`display: none`); the panels are given no `role="tabpanel"`, `aria-labelledby` or `tabindex` (the sample's panels are bare divs).
- Selection on click, Enter and Space; every arrow key moves to the previous/next sibling **and selects it** (automatic activation), without wrapping; no Home/End. Roving `tabindex` (selected 0, others -1). `default` names the panel id selected first.
- Layout: by default a 350px column of stacked tabs on the left (`--ilw-tabs--tablist-width`), panels on the right, 60px gap, `60px 30px 75px` padding, `--ilw-color--background`. `horizontal` puts the tabs in a row over the panels with a 2px rule under it. Under 800px (container query) the tabs stack full width above the panel.
- Tabs: `control` background, `control-text` colour, 1.1875rem bold sans, `.75em 1em` padding, 2px `control-text` rule under each (and over the first); hover swaps the two colours; selected is `control-accent` / `control-accent-text`; focus is the link focus colours. `rounded` rounds the tab's outer corners (1.5rem) and uses Storm 80.
- Attributes: `theme` (white, gray, blue, orange, blue-gradient, orange-gradient), `width` (full, auto, page), `horizontal`, `rounded`, `default`.

## Decisions

- **The no-JS form is the contract.** `.ilw-tabs > .ilw-tabs-container > section.ilw-tabs-panel[id] > h3.ilw-tabs-heading + content`. Without script it is a themed box of headed sections; an in-page link to a panel's id scrolls to it.
- **One enhancer.** `TabList.svelte` is the tab list: it reads the tabs (panel id + heading text), renders `div[role=tablist]` of `button[role=tab]`, and sets the panels' `role="tabpanel"`, `aria-labelledby`, `tabindex="0"` and `hidden`, restoring them when it is destroyed. `.ilw-tabs--ready` on the host hides the headings visually (they stay in the heading outline for screen readers).
  - `Tabs.svelte` renders the sections from a `tabs` array of `{ id, label, content }` (content a snippet) and adds `TabList` once mounted, so SSR sends the headed sections.
  - `enhanceTabs(host)` / `enhanceAllTabs(root)` mount `TabList` into server markup, options from `data-*` attributes (as `enhanceSelect`). `enhanceTabs` returns a cleanup, so it works as `{@attach}`.
- **APG behaviour, manual activation by default.** Arrows move focus with wrap; Home/End; Enter/Space/click select. `automatic` selects on focus (the toolkit's behaviour). All four arrows work in both orientations, because the horizontal list stacks into a column at narrow widths.
- **Hash links.** A URL fragment naming a panel (or anything inside one) selects that tab, on load and on `hashchange`. With `hash`, choosing a tab also writes `#<panel id>` with `history.replaceState` (no history entry per click).
- **Ids.** A tab's id is `<panel id>-tab`.
- **Styling** in `src/styles/tabs.css` (the house pattern since A5: one partial per component), with the toolkit's `--ilw-tabs--*` properties and values, the theme attribute and `.ilw-width-*`. Grid layout: tab list column + panel column; `.ilw-tabs--horizontal` stacks them. Container query under 800px, as upstream.
- **Not carried over:** `default` becomes `selected`; the `[slot=tabs]` tablist markup (the tab list is generated); upstream's mutation observer (Svelte re-renders; server pages call `enhanceTabs` again after a swap).
